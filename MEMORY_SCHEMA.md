# MEMORY_SCHEMA — Wiki Conventions and Page Templates

Pi-Memory generates and maintains an Obsidian-compatible markdown wiki. This document defines the conventions for pages, frontmatter, links, and structure.

## Page Types

### Concepts

Technical patterns, frameworks, algorithms, architectural ideas.

```markdown
---
tags: [concept, project-name]
created: YYYY-MM-DD
updated: YYYY-MM-DD
tier: L1
sources: [session-id]
---

# Title

## Summary
One-paragraph description of what this is and why it matters.

## Key Points
- 3-5 bullets of the most important facts
- Each bullet should be self-contained

## Details
2+ paragraphs of deeper explanation. Include:
- When to use this
- Common pitfalls
- Best practices

## Related
- [[concepts/related-concept]]
- [[entities/related-tool]]
```

### Entities

Libraries, APIs, tools, services, file types.

```markdown
---
tags: [entity, project-name]
created: YYYY-MM-DD
updated: YYYY-MM-DD
tier: L1
sources: [session-id]
---

# Entity Name

## Summary
What this entity is (1-2 sentences).

## Usage in this project
How it was used, with specific examples from sessions.

## Alternatives
- [[entities/alternative]] — when to choose it instead

## Related
- [[concepts/concept-that-uses-this]]
```

### Decisions

Architectural decisions, tradeoffs, ADRs.

```markdown
---
tags: [decision, project-name]
created: YYYY-MM-DD
updated: YYYY-MM-DD
tier: L1
status: accepted | rejected | superseded
sources: [session-id]
---

# Short Title of Decision

## Context
What problem needed solving.

## Decision
What was chosen.

## Consequences
### Positive
- Benefit one
- Benefit two

### Negative
- Cost one
- Cost two

## Status
Accepted / Rejected / Superseded by [[decisions/newer-decision]]

## Related
- [[decisions/related-decision]]
```

### Errors

Bugs, issues, gotchas, and their resolutions.

```markdown
---
tags: [error, project-name]
created: YYYY-MM-DD
resolved: YYYY-MM-DD | unresolved
tier: L1
sources: [session-id]
---

# Error Description

## Symptom
What went wrong.

## Root Cause
Why it happened.

## Fix
How it was resolved.

## Prevention
How to avoid it in the future.
```

### Profile

User preferences, patterns, role definition.

```markdown
---
tags: [profile]
created: YYYY-MM-DD
updated: YYYY-MM-DD
pin: true
---

# Title

## Observed Patterns
- Pattern one
- Pattern two

## Preferences
- Prefers X over Y
- Dislikes Z

## Notes
Free-form observations.
```

## Frontmatter Fields

| Field | Required | Description |
|---|---|---|
| `tags` | Yes | `[type, project-name]` where type is concept/entity/decision/error/profile |
| `created` | Yes | ISO date `YYYY-MM-DD` |
| `updated` | No | Last modification date |
| `tier` | Auto | `L1` \| `L2` \| `L3` \| `archive` — set by system |
| `pin` | No | `true` to prevent automatic tier demotion |
| `status` | Decisions only | `accepted` \| `rejected` \| `superseded` |
| `sources` | No | Array of session IDs that contributed to this page |
| `original_tier` | Auto | Set during tier transitions |
| `compressed` | Auto | Date when content was last compressed |

## Wiki-Links

Use Obsidian-style `[[path/slug]]` for internal links:

```markdown
See [[concepts/react-hooks]] for details.
This replaces [[entities/axios]] with [[entities/fetch]].
```

Rules:
- Always link to the **path**, not the title: `[[concepts/react-hooks]]` not `[[React Hooks]]`
- Every concept/entity page should have at least 2 outbound links
- Every decision should link to related decisions
- Profile pages should not have outbound links (they're the root)

## Directory Structure

```
global-wiki/
├── index.md              -- Auto-generated wiki index
├── log.md                -- Compilation log (append-only)
├── lint-reports/         -- Auto-generated health reports
├── benchmarks/           -- Auto-generated benchmark reports
├── profile/
│   ├── role.md           -- User role and goals
│   ├── preferences.md    -- Tool/framework preferences
│   └── patterns.md       -- Coding/workflow patterns
├── concepts/             -- Technical knowledge
├── entities/             -- Tools, libraries, APIs
├── decisions/            -- ADRs and tradeoffs
└── errors/               -- Bugs and resolutions

projects/{project-name}/
├── index.md              -- Project overview
├── concepts/             -- Project-specific concepts
├── entities/             -- Project-specific entities
└── decisions/            -- Project-specific decisions
```

## Index Pages

### Global Index

`global-wiki/index.md` is auto-generated by compilation. Format:

```markdown
# Pi-Memory Index

Generated: YYYY-MM-DD

## Concepts (N)
- [[concepts/concept-one]] — Short description
- [[concepts/concept-two]] — Short description

## Entities (N)
- [[entities/entity-one]] — Short description

## Decisions (N)
- [[decisions/decision-one]] — Short description

## Errors (N)
- [[errors/error-one]] — Short description
```

### Project Index

`projects/{name}/index.md` mirrors the global index but scoped to the project.

## Compilation Log

`global-wiki/log.md` is append-only:

```markdown
# Compilation Log

## [YYYY-MM-DD HH:MM] compile | Compiled N sessions into X new pages and Y updated pages ($0.0042)
## [YYYY-MM-DD HH:MM] compile | Compiled N sessions into X new pages and Y updated pages
```

## Link Types

The `links` table tracks relationship types:

| `link_type` | Meaning |
|---|---|
| `reference` | Mentions or links to (default) |
| `contradiction` | Says something opposite |
| `supersedes` | Replaces an older page |
| `related` | Related but not directly linked |

Contradictions are flagged by the lint system but must be resolved manually.

## Natural Language Pinning

Say "remember this" or "pin this" in conversation. The hook auto-detects it and:

1. Flags the session for priority compilation
2. Creates a "📌 Pinned Notes" section in the raw log
3. Compile prompts treat it as HIGH PRIORITY
4. Resulting wiki pages get `pin: true` automatically

You can also pin manually:

```markdown
---
title: Critical Security Decision
pin: true
---
```

Pinned pages stay at their current tier forever (unless manually changed).

## Tier Visualization

In Obsidian, you can color-code pages by tier using CSS snippets:

```css
/* dataview inline field styling */
[data-key="tier"] .dataview.inline-field-value[data-value="L1"] { color: green; }
[data-key="tier"] .dataview.inline-field-value[data-value="L2"] { color: orange; }
[data-key="tier"] .dataview.inline-field-value[data-value="L3"] { color: red; }
[data-key="tier"] .dataview.inline-field-value[data-value="archive"] { color: gray; }
```

## Recommended Obsidian Plugins

| Plugin | Purpose |
|---|---|
| **Graph View** (built-in) | Visualize wiki-links between pages |
| **Dataview** | Query frontmatter (e.g., "all L1 concepts from project X") |
| **Templater** | Templates for new wiki pages |
| **Obsidian Git** | Auto-commit/push every 10 min, auto-pull on startup |

### Obsidian Git Config

Settings → Obsidian Git:
- Vault backup interval: `10`
- Auto backup after file change: ON
- Auto pull on startup: ON
- Commit message: `vault: {{hostname}} {{date}}`
